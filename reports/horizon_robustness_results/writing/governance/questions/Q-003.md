Question: How does measuring historical blocks against a pooled reference that contains them bias the drift (TV) and station-dispersion comparisons?
Why it changes acceptance: It decides whether "beyond the historical maximum" and the margin-rule dispersion figures can be stated as stored.
Decisive test (read/recompute/none): read tools/horizon_robustness/drift_survey.py:12-18 and dispersion_survey.py:11-13; verify the identity TV(block, pooled) = (1 - w) TV(block, rest); recompute anchors drift.holdout.* and disp.explor.*.like_for_like
Class: E
Options, most to least conservative (or UNORDERED): n/a (Class E)
Ordering confirmed by: n/a
Conservative default: report stored and like-for-like values together, stating the reference each is measured against
Card-specific decision rule (if any): none
Resolution: E. Both surveys measure each history block against a pooled reference that contains that block. In drift_survey.py (lines 13-14 and 83-87), the TV of each right-aligned n-block is taken against the pooled history of the same prefix. In dispersion_survey.py (lines 10-13), each block share is taken minus the pooled share b_s. Write the pooled mix as P = w B + (1 - w) R, where B is the block and R the rest of the history. Then TV(B, P) = (1 - w) TV(B, R) and d(B, P) = (1 - w) d(B, R), so every stored block-versus-pooled value is smaller than the block-versus-rest value by the factor (1 - w). The like-for-like anchors divide by (1 - w). They take w by order count, because block line mass is not stored, and the paper discloses that. The paper reports each stored value next to its like-for-like value and names the reference each one is measured against. Both independent anchor computations (seq 27 and seq 36) agree on these values, pending gate P1:G1.
