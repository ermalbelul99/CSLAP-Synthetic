## Question

In `W/evidence/ANCHOR_SPEC.md`, which arm tokens does `<ARM>` expand to in rows that carry no local arm list? This affects every Section A row pattern (for example `ho.pass.<ARM>.count` and `ho.visits.<ARM>.<SEED>`) and the Section C pattern `ts.berner.<DELTA>.pass.<ARM>.count`.

## Why it matters

Without a local list, the rows fall back to all five convention arms: NOM, TIGHT, HIST_ACT, HIST_ACT_T and HIST. That would require keys for arms that no campaign ran. Neither blind builder could produce them, and the rows are not optional, so `compare_anchors.py` would fail by construction. The two builders might also resolve the ambiguity differently.

## Decisive test

ORCH read `reports/horizon_robustness_results/tables/case_frame.csv` read-only (pandas, grouped by `campaign` and `arm`, 14 Sep 2026). The arms present are:

| Campaign | Arms present (rows) |
|---|---|
| `ho3_20260913` | HIST+ACT (3), HIST+ACT-T (3), NOM (3), TIGHT (3). No HIST. |
| `ts_b01_20260912` | HIST (3), HIST+ACT (3), NOM (3), TIGHT (3). No HIST+ACT-T. |
| `ts_d02_20260912` | HIST (15), HIST+ACT (15), NOM (15), TIGHT (15). No HIST+ACT-T. |
| `ts_b03_20260912` | HIST (3), HIST+ACT (3), NOM (3), TIGHT (3). No HIST+ACT-T. |
| `screen_20260910` | HIST (90), HIST+ACT (90), NOM (90), TIGHT (90). |

## Options

- (a) Five-arm fallback everywhere. This is what the check author implemented, and it fails by construction.
- (b) Explicit per-row arm lists that match the campaigns actually run.

## Resolution

Resolution: (b), by case-frame evidence.
- Every Section A row with `<ARM>` gets `for NOM, TIGHT, HIST_ACT, HIST_ACT_T`.
- The Section C two-sided pass-count row is split into one row per δ (d01, d02, d03), each with `for NOM, TIGHT, HIST, HIST_ACT`. `compare_anchors.py` accepts one local restriction per row, and the key names do not change.

ORCH applies the edit before any anchor builder is dispatched, and verifies the expanded key set on a scratch copy.
