## Question

`compare_anchors.py` and `check_claims.py` confirm their repository root by checking that `WRITING_ORCHESTRATION_PLAN_20260914.md` exists there, and they do this whether or not `--root` was given. Should the check apply unconditionally, or only when `--root` is not given?

## Why it matters

With an unconditional check, every fixture tree needs a one-line stub file, and a check run against a wrong `--root` fails loudly. With the check limited to the default root, a mistyped `--root` could run against the wrong tree. It would then pass or fail on unrelated files.

## Options (most conservative first)

- (a) Unconditional marker check. This is what the author implemented; the fixtures carry a stub.
- (b) Marker check only when `--root` is not given.

## Conservative default

(a).

## Resolution

Resolution: (a), the unconditional marker check. code-reviewer/opus (seq 26) confirmed that (a) is more conservative because it fails closed on a wrong --root, and chose (a) (W/governance/results/P1-026-code-review-checks.md).
