## Question

The "Allowed sources" list in `W/evidence/DOCUMENT_VALUES_SPEC.md` had one bullet holding a full path, `reports/horizon_robustness_results/CAMPAIGN_PREDECLARATION.md`, followed by three bare filenames: `DATA_PROVENANCE.md`, `analysis_audit.md` and `EXPERIMENT_REVIEW_HANDOFF.md`.

Do the bare filenames share the directory of the full path before them? Or must each fragment be a complete path?

## Why it matters

`compare_anchors.py --documents` now restricts `source.path` to the allowed sources (finding F-050). If each fragment had to be a complete path, the checker would reject real sources.

## Decisive test

1. The three files exist at `reports/horizon_robustness_results/DATA_PROVENANCE.md`, `reports/horizon_robustness_results/analysis_audit.md` and `reports/horizon_robustness_results/EXPERIMENT_REVIEW_HANDOFF.md`.
2. Both blind extractions cited exactly those full paths: `W/governance/results/P1-029-docvalues-A.md` (seq 29) and `P1-030-docvalues-B.md` (seq 30).
3. ORCH checked every such source: each path exists, each SHA-256 matches, and each quote occurs on its line.
4. Neither the repository root nor any other directory holds files with those names that the specification could mean.

## Options

- (a) The bare filenames inherit the directory of the preceding full path. This is what the check author implemented.
- (b) Each fragment must be a complete path.

## Resolution

Resolution: (a) as to meaning. The ambiguity itself is removed at its source. ORCH rewrote the bullet as four bullets, each holding one full path, so the list no longer depends on any parsing convention.

The inherit-prefix parsing in `compare_anchors.py` may remain. The P1 code re-review 1 is asked to confirm that the rewritten list parses to the same seven allowed sources.
